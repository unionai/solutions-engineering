AI Agent Builders

Durable, observable, self-healing agents, with tools that run on the cluster.

The old way

  • Agent state lives in RAM, so a restart loses it
  • Limited visibility into why a tool was called
  • Model-written code runs with exec()

    • With Union

  • Durable state & sleep-wake survive restarts
  • Every tool call traced & visible in the UI
  • Untrusted code runs in an isolated sandbox
    • ⬡ union.aiAI Agents

    Tools that are durable tasks

    from flyte.ai.agents import Agent

agent = Agent(
    name="research-agent",
    instructions="You are a helpful analyst.",
    model="claude-haiku-4-5",
    tools=[search, run_query],   # @env.task = runs ON the cluster
    mcp_servers=[github, slack], # external tools via MCP
    max_turns=25,
    parallel_tool_calls=True,
    code_mode=False,             # or: LLM writes Python in a sandbox
)
result = await agent.run.aio("Analyze Q3 risk")
    • A tool can be any callable, including an @env.task that runs durably and distributed
    • MCP servers (GitHub, Slack, Linear) surface in transparently
    • Memory store persists history + artifacts with concurrency control
    ⬡ union.aiflyte.ai.agents.Agent

    The model writes the code, the sandbox runs it

    agent = Agent(
    name="analyst",
    model="claude-haiku-4-5",
    tools=[fetch_rows, score, save],   # exposed as plain Python fns
    code_mode=True,    # LLM writes a program each turn,
)                      # not JSON tool calls

# Each turn the LLM emits Python, run in the Monty sandbox via
#   flyte.sandbox.orchestrate_local(...)
# The last expression becomes the next observation.
    • Generated control flow: loops, flyte_map fan-out, and intermediate aggregation, all in one turn
    • Tools are still @env.task, so they dispatch durably on-cluster from inside the program
    • Runs in the Monty sandbox: memory cap, stack-depth cap, timeout, type-checked

    requires pydantic-monty in the image

    ⬡ union.aicode_mode=True

    Run untrusted code safely

    # Stateless, ephemeral container: fresh every run
sandbox = flyte.sandbox.create(
    name="run-llm-code",
    code=generated_code,            # code the model wrote
    inputs={"x": int}, outputs={"result": int},
    resources=flyte.Resources(cpu=1, memory="1Gi"),
)
result = await sandbox.run.aio(x=21)   # network blocked, timed out

# Nested on-cluster sandboxes (bubblewrap), opt in per env:
env = flyte.TaskEnvironment(name="grpo",
    pod_template=flyte.PodTemplate().allow_nested_sandboxing())
    • No exec() in your process: isolated container, no state carryover
    • Network-blocked, resource-capped, timed-out by default
    • Perfect for RL reward functions & agents that execute model-written code
