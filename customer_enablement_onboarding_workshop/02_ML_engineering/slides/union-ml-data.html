The old way

    Scale a function across N inputs

    @env.task
async def classify_ticket(ticket: dict) -> dict:
    ...

# Fan out across the whole batch
@env.task
async def triage(tickets: list[dict]) -> list[dict]:
    return list(flyte.map(classify_ticket, tickets))

# ...or the async idiom for full control
results = await asyncio.gather(
    *(classify_ticket(t) for t in tickets)
)
    • flyte.map(fn, items) distributes across the cluster
    • Each item gets its own retries, cache, resources
    • Higher-order patterns: auto-batcher, circuit breaker, fallback runner

    ML & Data Science

    From a notebook to distributed GPU training to a deployed model.

    The old way

  • Scarce GPUs sit idle between runs
  • A spot interruption means restarting a long run
  • Hard to trace which data + code produced a model

    • With Union

  • GPU per task, scale-to-zero when idle
  • Checkpoints resume across crashes & spot interruptions
  • Every model pinned to an immutable code+data version
    • ⬡ union.aiMachine Learning

    Hyperparameter sweeps in a gather

    gpu_env = env.clone_with(
    name="train",
    resources=flyte.Resources(cpu=6, memory="16Gi",
                              gpu="A100:1"))

@gpu_env.task
async def sweep(grid: list[dict]) -> dict:
    models = await asyncio.gather(
        *[train.aio(p) for p in grid])      # N trainings, in parallel
    evals  = await asyncio.gather(
        *[evaluate.aio(m) for m in models])
    return best(models, evals)
    • Each trial = its own GPU pod, retries, cache
    • Typed accelerators: GPU, TPU, and more + MIG partitions
    • Warm ReusePolicy pods → no per-trial cold start

    Hit an OOM → recover with more memory

    import flyte, flyte.errors

while memory_mi <= max_memory_mi:
    mem = f"{memory_mi}Mi"
    try:
        # re-run the SAME task with more memory
        return await task_fn.override(
            resources=flyte.Resources(memory=mem)
        )(*args, **kwargs)
    except flyte.errors.OOMError:
        memory_mi += increment_mi   # bump & retry
# (real: examples/higher_order_patterns/oom_retrier.py)

    flyte.errors.OOMError is a real, catchable exception, not a crash you lose the run to.

    Attempt 1
    › running task @ memory: 250Mi
    ✗ OOMError: container exceeded 250Mi
    Attempt 2
    › running task @ memory: 450Mi
    ✗ OOMError: container exceeded 450Mi
    Attempt 3
    › running task @ memory: 650Mi
    ✓ Success with memory: 650Mi

    Ship the last mile: apps & models

    from flyte.app.extras import FastAPIAppEnvironment

app_env = FastAPIAppEnvironment(
    name="model-api", app=app,
    resources=flyte.Resources(gpu=1),
    scaling=flyte.app.Scaling(
        replicas=(0, 3),            # scale-to-zero → burst to 3
        scaledown_after=1800),
    parameters=[flyte.app.Parameter(name="model",
        value=flyte.app.RunOutput(           # mount a trained
            task_name="finetune.pipeline", type="directory"))],
)
flyte.serve(app_env)        # or: flyte serve serving.py app_env
    • First-class deployments next to your pipelines, sharing the same image, secrets, and versioning
    • FastAPI · Streamlit · Gradio · Panel · MCP servers · agent chat UIs
    • Scale-to-zero (0,1) · always-on (1,1) · HA (2,10)
    • RunOutput wires a model artifact straight from a training run
    • Custom Domain, auth, and Links between apps
